# `rayTriangleIntersect()` 检查与改进建议

## 结论

当前 `Triangle.hpp` 中的 `rayTriangleIntersect()` 没有发现功能性算法错误，可以正确完成双面三角形求交，并在成功时输出 `tnear`、`u`、`v`。

本次检查只评审和验证用户已经完成的实现，没有修改作业算法源码。

## 已验证内容

### 工程级验证

- 使用 MSYS2 UCRT64、CMake 和 Ninja 完成全量重新构建。
- 编译、链接成功，没有来自 `rayTriangleIntersect()` 的警告。
- `RayTracing.exe` 正常退出。
- 成功生成 1280 × 960 的 `binary.ppm`。
- 最终图像中能够看到棋盘地面、纹理插值、球体阴影和透明球对地面的折射。

### 独立求交用例

以下用例全部通过：

1. 从三角形正面击中内部。
2. 从三角形背面击中内部。
3. 击中三角形边界。
4. 击中三角形顶点。
5. 交点位于 `u < 0` 的三角形外部区域。
6. 交点满足 `u + v > 1`，位于另一侧外部区域。
7. 射线平行于三角形平面。
8. 平面交点位于射线起点后方。
9. 三个顶点共线的退化三角形。

## 当前实现正确的关键点

- 使用 `E1 = v1 - v0` 和 `E2 = v2 - v0` 建立三角形局部基。
- `det` 使用的叉积顺序与 `t/u/v` 分子保持一致。
- 使用 epsilon 排除平行射线和退化三角形。
- 同时检查 `u >= 0`、`v >= 0` 和 `u + v <= 1`。
- 排除位于射线起点后方或过近的交点。
- 只在所有检查通过后更新 `tnear`、`u`、`v`，失败分支不会留下部分输出。
- 对 `det` 使用绝对值判断，因此正面和背面的射线都能求交。

## 改进建议

以下建议不影响当前作业得分点，主要改善可读性、效率、头文件健壮性和后续扩展能力。

### 1. 让 `Triangle.hpp` 自包含

`Triangle.hpp` 直接使用了：

- `std::unique_ptr`；
- `std::fabs`。

但目前只直接包含了 `<cstring>`，`<memory>` 和 `<cmath>` 依赖其他头文件的间接包含。主工程当前可以构建，是因为包含顺序刚好提供了这些声明；独立包含 `Triangle.hpp` 时会因找不到 `std::unique_ptr` 而失败。

建议让每个头文件直接包含自己使用的标准库头：

- 为 `std::unique_ptr` 直接包含 `<memory>`；
- 为 `std::fabs` 直接包含 `<cmath>`。

这样更换包含顺序或在新测试文件中单独引用该头文件时仍能正常编译。

### 2. 缓存 `1 / det`

当前实现三次计算：

```text
1 / det
```

可以先保存一个只读的 `invDet`，后续通过乘法使用。

优点：

- 明确表达“行列式只取一次倒数”；
- 避免重复除法；
- 更接近常见的 Möller-Trumbore 推导结构。

### 3. 缓存两个叉积辅助向量

当前实现重复计算了两组相同叉积：

- `dir × E2` 同时用于 `det` 和 `u`；
- `S × E1` 同时用于 `t` 和 `v`。

可以分别保存为有意义的辅助变量，例如推导中常见的 `pvec` 和 `qvec`。

优点：

- 避免重复计算；
- 叉积顺序集中在一个位置，更不容易产生符号错误；
- 代码结构能直接对应课程公式。

### 4. 按推导顺序尽早返回

当前实现先计算 `t_temp`、`u_temp`、`v_temp`，然后统一检查。

更常见的顺序是：

1. 计算并检查 `det`；
2. 计算并检查 `u`；
3. 计算并检查 `v`；
4. 最后计算并检查 `t`。

大量射线会在重心坐标阶段落到三角形外部。尽早返回可以避免这些失败射线继续计算剩余变量。

对本作业只有两个三角形的场景，性能差异很小；这个习惯在大型三角形网格中更重要。

### 5. 为不再修改的局部量增加 `const`

边向量、辅助向量、`det`、临时重心坐标等在初始化后不会再次赋值，可以声明为只读局部量。

优点：

- 明确变量生命周期中的不变量；
- 防止后续维护时意外改写；
- 让读者更容易区分中间结果和最终输出参数。

### 6. 区分 determinant epsilon 与 ray epsilon

当前 `isZero()` 的默认 epsilon 同时可能用于：

- 判断 `det` 是否接近零；
- 判断 `t` 是否离射线起点过近。

两者表达的物理意义不同：

- determinant epsilon 控制近平行和退化判断；
- ray epsilon 控制自相交和射线起点附近的命中。

当前场景尺度下统一使用 `1e-6` 可以正常工作。若未来场景尺寸差异很大，建议给两种容差起独立名称，并根据模型尺度选择数值。

另外，`det` 的大小还受到三角形面积影响，固定绝对 epsilon 对极小或极大的三角形并不完全具有尺度不变性。这属于进阶健壮性问题，不是本次作业要求。

### 7. 使用更直接的正向距离判断

当前逻辑分别判断：

```text
t_temp < 0
t_temp 接近 0
```

可以在语义上合并为“`t_temp` 必须大于射线 epsilon”。这样更直接地表达：只接受位于射线前方并且与起点保持安全距离的交点。

### 8. 收紧辅助函数的作用域与书写方式

`isZero()` 已经添加 `inline`，避免了头文件被多个翻译单元包含时的重复定义问题。

仍可考虑：

- 使用更常见的 `inline bool` 顺序；
- 使用更具体的名称，说明它比较的是浮点数绝对值；
- 将通用性不强的辅助函数限制在适当命名空间中，避免污染全局命名空间。

这些都是代码组织建议，不影响当前行为。

### 9. 更新已经完成的 TODO 注释

函数已经实现，但头部仍保留 `TODO: Implement this function`。

建议改成普通功能说明，避免之后搜索 TODO 时误以为该函数尚未完成。下面的中文步骤清单可以保留为学习记录，也可以压缩成算法概述。

### 10. 保留一组小型边界测试

最终渲染图能够验证整体效果，但不容易单独发现边界问题。建议在个人学习阶段保留几组小型测试思路：

- 三角形内部命中；
- 正反面命中；
- 边和顶点命中；
- 三角形外部；
- 平行射线；
- 射线后方；
- 退化三角形。

提交课程作业时是否携带测试文件，应以课程提交结构要求为准。

## 建议的改进优先级

如果只做少量整理，推荐顺序为：

1. 补齐 `<memory>` 和 `<cmath>`，让头文件自包含。
2. 缓存 `invDet`、`pvec`、`qvec`。
3. 按 `det -> u -> v -> t` 顺序尽早返回。
4. 清理完成后的 TODO 注释。
5. 最后再考虑独立 epsilon、命名空间和尺度相关容差。

这些改进都不要求改变 Möller-Trumbore 的数学结果。当前版本已经能够正确完成 Assignment 5 的三角形求交得分点。
