## 2. Phong：计算要求与约定

对应作业基础项 20 分；函数名虽是 phong，实际实现的是使用半程向量的 Blinn–Phong。normal 检查管线与法线，phong 检查光照。

输入是当前片元 payload，输出是最终 RGB 浮点向量，尺度为 0–255。本阶段不需要查询纹理、修改光栅化器或计算 bump。

### 输入与计算

- point：payload.view_pos，观察空间着色位置。
- n：单位法线，来自 payload.normal。
- kd：payload.color，已经是 0–1 尺度，不再除以 255。
- ka、ks、p：使用函数预设的环境光系数、高光系数和高光指数。
- 每盏灯：位置及 RGB intensity。

对每盏灯，构造 light.position-point，计算距离平方 r² 和单位光照方向 l；构造观察者位置-point 得到单位观察方向 v；计算 h=normalize(l+v)。

三个分量为：

```text
ambient  = ka ⊙ ambient_intensity
diffuse  = kd ⊙ (intensity / r²) × max(0, n·l)
specular = ks ⊙ (intensity / r²) × pow(max(0, n·h), p)
```

⊙ 表示 RGB 逐分量相乘，对应 Eigen 的 cwiseProduct；点积用 dot。环境光不依赖方向或距离。累加结果后，函数末尾已有乘以 255，不要重复缩放。

### 坐标空间与课程约定

所有用于位置相减的量必须在同一空间。payload.view_pos 和法线来自观察空间；严格采用该空间时相机在原点。框架 shader 里预设 eye_pos=(0,0,10)，与 main 中世界空间相机位置相同，不能在概念上直接等同于观察空间相机坐标。

若将预设灯位置理解为世界空间，当前相机只做平移，灯应转换为 light.position-(0,0,10)，观察者使用原点。若为对照课程示例保留原 shader 数值约定，需要明确它与严格一致坐标空间的区别，图像高光位置可能不同。

框架 TODO 将 ambient、diffuse、specular 都写在逐灯循环中，按该提示每盏灯加一次环境项会累计两次。常见的全局环境光模型则在循环外只加一次环境项。选择课程约定时应保持一致，不要在循环内外重复添加。

### 验收

在 Assignment3_code/build-ucrt 中执行：

```powershell
./Rasterizer.exe normal.png normal
./Rasterizer.exe phong.png phong
```

预期 phong 显示棕色模型、明暗层次和局部高光。可分阶段检查：仅环境光看底色，再加漫反射看朝向明暗，最后加高光检查观察方向和半程向量。法线颜色模式不用于证明光照公式正确。

Texture 使用同样的光照计算，将 kd 的来源改为纹理采样颜色除以 255。

### Phong 可选改进

光照方向、观察方向、半程向量、距离平方衰减和高光指数按框架公式组织；统一坐标空间后的效果对照尚未进行。

当前保留框架 eye_pos 和逐灯累加环境光的写法。坐标空间一致性问题见上文，不因图像能够生成而自动消失。以下建议不代表要求立即修改，本次只记录文档。

### 优先考虑：保持当前模型与参数约定的整理

1. **把观察方向放到灯光循环外计算。** 对一个片元，point 和 eye_pos 不随灯变化，因此 v 只需计算一次。采用哪种空间写法仍由前述约定决定。
2. **复用到灯光的位移和衰减结果。** 先保存 Vector3f light_delta = light.position - point，用它计算 squaredNorm 和单位方向；再保存 Vector3f irradiance = light.intensity / r_squared，给漫反射与高光共用，避免重复表达式。
3. **避免每个片元创建动态灯光数组。** 固定两盏灯可使用栈上的 light lights[] = {l1, l2}，或 std::array<light, 2>（应明确包含 array 头文件）。相比当前 vector，可避免逐片元的动态分配。只有光源数量固定时才适合这样处理。
4. **把 ambient 的计算移到循环外，但保留原有累加次数。** 若保持框架效果，可以循环外计算一次 ambient，循环内继续加一次，不能把“少算几次”与“少加几次”混为一谈。
5. **删除未使用的 color 变量，使用 const。** kd 已经保存 payload.color；遍历灯光可写 const auto&，位置、材质系数和指数等不变数据也可标记 const。完成后的 TODO 可替换为解释光照约定的简短注释。

复用向量表达式时建议使用显式 Eigen::Vector3f 保存结果；Eigen 的 auto 可能保存延迟求值表达式，并不一定立即生成独立向量。不要为减少几行代码引入临时对象生命周期问题。

### 可选：健壮性与模型约定

- 距离平方接近零时，不直接计算 intensity/r²；明确采用跳过该灯贡献或受控的最小距离策略。固定场景通常不触发，但通用 shader 应处理。
- 观察方向长度或 l+v 长度接近零时，不能把归一化结果当作有效方向。半程向量无效时可以令高光贡献为零，并保留有效的漫反射和环境项。
- 当前光栅化器已对法线归一化，shader 不必重复做；若将来独立调用，应约定输入法线为有限非零单位向量，或由 shader 做相应检查。
- 若采用单面反射模型，可在 n·l<=0 时同时关闭直接漫反射与高光，避免背光面仍出现高光。这会改变框架原始公式的行为，应作为模型选择单独验收。
- 把环境光改成全局仅累加一次、或统一观察者与灯光坐标空间，都会改变图像，不能作为纯性能优化静默进行。

### 建议实施顺序

先做观察方向外提、复用 light_delta 与 irradiance、去掉逐片元 vector 分配。必要时再补异常输入处理；坐标空间与环境光约定通过独立对照图检查。不要求为这些建议暂停后续 texture_fragment_shader 的学习。

验证任何实际改动时，使用相同相机、角度、灯光和输出模式比较；纯计算整理应保持视觉一致，浮点运算重排可能造成极小差别。目前没有针对上述可选优化修改源码或开展性能基准测试。

## 3. Texture：采样与改进建议

当前数据流为 payload.tex_coords → getColor → RGB/255 → kd → Blinn–Phong。默认模型效果包含贴图、明暗和高光；边界输入限制如下。

### 已知限制：采样边界（暂缓扩展）

当前 shader 直接使用 UV，Texture::getColor 也未限制行列范围。其列=u*width、行=(1-v)*height，在 u=1 或 v=0 时会访问边界外；UV 超出范围时同样存在问题。这是仍未处理的正确性边界问题，不只是性能优化。

采样策略可以选择边缘钳制。若允许修改 Texture，统一在采样函数里将最终整数行列限制为 [0,width-1] 和 [0,height-1]，并在浮点转整数前检查有限性与范围，会比每个 shader 各自处理更一致。若限制只能修改 shader，应在调用 getColor 前使用与其映射匹配的安全坐标；只 clamp UV 到闭区间 [0,1] 不足以保护端点。以后 bump 的邻居查询也必须应用同样策略。

### 可选整理与扩展

1. 简化 return_color → texture_color 的重复复制，可以直接初始化一个 texture_color 并将查询结果赋给它。
2. 删除未使用的 color 变量，更新已经完成的 TODO 注释。
3. 沿用上一节建议：观察方向和环境项计算外提、复用 light_delta 与 irradiance、固定灯光数组避免每个片元动态分配。
4. 明确缺失纹理时的策略。当前空指针分支令 kd 为零，仍有环境光和高光，不会完全黑屏；可选择回退到 payload.color，或明确拒绝缺失纹理。回退会改变行为，不是必需的作业功能。
5. 双线性纹理采样属于加分项，可等 bump/displacement 完成后再做，配合小尺寸纹理提供普通采样与双线性采样对照。
6. 如果后续允许提取辅助函数，可将 phong 与 texture 的公共光照计算提取出来，以 kd 作为参数，减少两套实现发生偏差；若只允许填写指定函数，保留重复代码并同步约定即可。

坐标空间和环境光累计次数依然沿用此前记录的框架约定。本次没有静默改变它们。

## 4. Bump：计算要求与改进建议

目标是用高度纹理改变片元法线，按现有框架输出扰动法线的颜色。此阶段不移动着色位置，不修改顶点或模型轮廓，也不要求复用整套 Blinn–Phong 光照；光照与位置扰动将在 displacement 阶段使用。

### 实现顺序

1. 读取并单位化 payload.normal，读取 UV，检查纹理是否存在及尺寸有效。bump 模式默认使用 hmap.jpg。
2. 构造切向量 t、副切向量 b 与法线 n，组成 TBN，以三个向量作为矩阵的列。检查它们是单位且相互垂直的向量。
3. 定义标量高度 H(u,v)。课程常见写法使用 getColor(u,v).norm()；这是 RGB 向量的长度，不是 normalized()。也可选灰度高度，但高度尺度会影响 kh、kn 的效果，不能随意换尺度后直接对比参考图。
4. 分别查询中心、u 方向相邻一纹素、v 方向相邻一纹素的高度，计算框架要求的差分：

```text
dU = kh * kn * (H(u + 1/width, v) - H(u,v))
dV = kh * kn * (H(u, v + 1/height) - H(u,v))
local_normal = (-dU, -dV, 1)
perturbed_normal = normalize(TBN * local_normal)
```

步长必须是浮点除法，如 1.0f/width。中心高度可只采样一次。这里按作业注释使用有限差分值，没有再除以步长；自行增加这一步会改变扰动幅度。

5. 将结果赋给框架随后输出的 normal。当前尾部是 normal*255，不是 normal_fragment_shader 的 (normal+1)/2*255；两种显示映射不能混为一谈。保留框架输出时负颜色分量会在 8 位转换中被截断；为了调试可以另选映射，但对比参考图时应使用一致映射。

### TBN 注释的数学注意点

当前源码注释给出 s=sqrt(x*x+z*z)、t=(x*y/s,s,z*y/s)。其与 n=(x,y,z) 的点积为 2*y*s，通常不为零，所以它不是严格正交的切向量公式。

若构造严格正交基，s 非零时可使用 t=(x*y/s,-s,z*y/s)，再令 b=n.cross(t)；n 接近 y 轴时需选择备用切线。也可选取不与 n 平行的参考轴，使用叉积构造正交基。切线方向会影响高度纹理的扰动方向；框架没有真实 UV 切线，这仍是作业中的局部基近似。若按原注释复现参考效果，应明确这一差异。

从 Assignment3_code/build-ucrt 运行 `./Rasterizer.exe bump.png bump`。应看到高度图对应的法线细节，模型轮廓保持不变。临时令 kh=0 或使用恒定高度时，输出方向应退化为原法线；比较 normal 模式时需考虑两者颜色映射不同。确认基本效果后，再进行 displacement_fragment_shader 的位置扰动和光照计算。

## 5. Displacement：计算要求与改进建议

当前实现复用高度差分和 TBN，计算扰动法线，同时沿原法线移动着色位置，并使用 Blinn–Phong 输出光照颜色。

### 数据与顺序

1. 保存原观察空间位置 P=payload.view_pos 和单位原法线 N=normalize(payload.normal)。
2. 查询中心高度 H0 和两个邻居高度，沿用 bump 的 TBN、差分及法线计算，得到新法线 N'。
3. 计算 P'=P+kn*N*H0。位置移动使用原法线 N，不能误用已覆盖的新法线；不对 P' 归一化。按框架该式使用 kn，不能随意额外乘 kh。
4. 使用 P' 和 N' 重新计算每盏灯的方向、距离平方、观察方向与半程向量，然后累计 Blinn–Phong 三项。方向和距离都应使用同一个 P'。
5. 保留 kd=payload.color；hmap.jpg 在这里提供高度，不是彩色材质纹理。保持高度尺度及坐标空间约定与前面一致；最终只乘一次 255。

相较 bump，输出变为光照后的 RGB，不再返回法线颜色。框架仅在片元着色时修改局部位置变量，不会重新投影、更新原三角形或重算 z-buffer，因此不会真正改变模型轮廓和遮挡，不等同于完整的几何位移。

### 验收

从 Assignment3_code/build-ucrt 运行 `./Rasterizer.exe displacement.png displacement`。预期出现高度细节对应的光照变化，不能以轮廓是否变化为验收条件。保持相同光照与空间约定，临时令 kn=0 时，法线和位置应恢复原状，结果应接近 phong 模式；恢复参数后再保存最终效果。后续实现检查见下一节。
