## 1. 先明确这个函数要交付什么

**输入一条光线，返回沿这条光线看到的线性 RGB 辐射亮度估计。**

- 相机调用时，它回答“这个像素的这次路径采样看到了多少光”。
- 递归调用时，它回答“从当前表面沿随机反弹方向看过去，有多少光可以带回来”。
- 返回值是 `Vector3f`，三个分量表示 RGB，不是交点坐标、材质颜色或法线。
- `depth` 表示当前反弹层数，相机起始为 0，每次递归传 `depth+1`。

对于非发光表面，本作业把结果拆成：

```text
当前光线的贡献 = L_direct + L_indirect

L_direct：从表面直接连接到灯的贡献
L_indirect：先到另一个非发光表面，再经过后续反射带回来的贡献
```

相机直接命中发光面则单独返回发光值。这里采用作业基础版的“显式采样光源 +
均匀半球反弹”策略；下文会说明为什么间接分支不能再次无条件计入撞灯贡献。

## 2. 先统一方向和变量，减少符号错误

建议你在纸上画出当前表面 `p`、灯点 `x` 和下一个表面 `q`，再使用下面的名字。

| 建议名字 | 来源/定义 | 含义 |
| --- | --- | --- |
| `hit` | 当前光线的交点结果 | 同一层只求一次即可 |
| `p` | `hit.coords` | 当前着色点 |
| `n` | `hit.normal` | 当前表面朝外的单位法线 |
| `material` | `hit.m` | 当前表面材质 |
| `travelDir` | `ray.direction` | 光线从上一点传播到当前点的方向 |
| `viewDir` | `-travelDir` | 当前点朝向上一点/相机的方向，帮助理解物理含义 |
| `lightSample` | `sampleLight()` 输出 | 采样结果容器，不等于一次真实求交 |
| `x`、`nLight`、`Le` | 灯采样的坐标、法线、`emit` | 灯面上的信息 |
| `toLight` | `normalize(x-p)` | 当前点指向灯点 |
| `r`、`r2` | 灯点距离及距离平方 | 几何权重使用未偏移的 `p` 与 `x` |
| `pdfArea` | `sampleLight()` 输出 PDF | 对灯面面积的密度 |
| `bounceDir` | `material->sample(...)` 输出 | 当前点指向下一次反弹位置的单位方向 |
| `pdfDirection` | `material->pdf(...)` 输出 | 对方向立体角的密度 |
| `L_direct/L_indirect` | 初始化为零 | 分别累加两类贡献 |

`travelDir` 与 `viewDir` 相反，不能混着使用。本框架的漫反射实现忽略材质函数的
第一个方向参数，基础版可以沿作业伪代码的约定，把 `travelDir` 作为第一个参数，
把 `toLight` 或 `bounceDir` 作为第二个参数。第二个方向必须是从当前点朝外的方向。

以后扩展 Microfacet 时，需要重新核对材质接口采用的入射/出射约定；
“漫反射下看起来一样”不能证明方向符号处处正确。

## 3. 八个可以依次完成的小任务

| 步骤 | 要完成什么 | 完成后应拿到什么 |
| --- | --- | --- |
| A | 处理当前光线是否命中 | 未命中时有明确返回 |
| B | 识别命中发光面，提取普通表面信息 | `p/n/material` 或直接返回发光值 |
| C | 在灯上取点并准备几何量 | `x/nLight/Le/pdfArea/toLight/r2` |
| D | 判断到这个灯点是否可见 | `visible` |
| E | 计算直接光 | `L_direct` |
| F | 用 RR 决定是否继续间接路径 | 继续或保留直接光并结束 |
| G | 半球采样、查询下一命中并递归 | `L_indirect` |
| H | 合并、返回并逐阶段验证 | `L_direct + L_indirect` |

### A. 当前光线是否命中

**你已基本完成这一部分。**

需求：

1. 对输入 `ray` 求场景交点。
2. 若 `happened=false`，返回黑色。
3. 命中后才能访问材质、坐标、法线。

对于当前 Cornell Box 基础任务，返回黑色表示没有环境光。`Scene` 中虽然有
`backgroundColor` 字段，也不代表必须把它作为环境辐射返回；随意使用会改变照明设定。

验收：一条明确射向场景外部的光线返回零，不访问空材质指针。

### B. 命中的是灯，还是普通表面

需求：

1. 取得 `hit.m`，确保它是有效材质。
2. 调用 `hasEmission()` 判断当前表面是否发光。
3. 如果发光，返回材质 `getEmission()` 的值，让相机能够直接看到灯。
4. 普通表面则提取 `p/n/material`，把两个贡献量初始化为零。

使用命中材质的发光值，不要依赖 `hit.emit`：你的三角形求交填写了材质，
没有额外填写 `Intersection::emit`。

**本篇配套策略：当前命中灯时可以返回发光值；但 G 步必须过滤间接采样撞灯，
只对非发光命中递归。** 不要只实现前半条、遗漏后半条，否则会重复计算直接光。
该策略针对当前纯漫反射基础版，不能直接推广到含理想镜面反射的路径。

阶段验收：暂时让普通表面返回黑色、发光表面返回 `Le`，先看见灯的轮廓。
这只是验证发光命中，不是最终结果。

### C. 在灯面采样，并计算方向和距离

使用接口：

```cpp
void Scene::sampleLight(Intersection& pos, float& pdf) const;
```

需求：

1. 创建 `Intersection lightSample`，将 `pdfArea` 初始化为 0。
2. 调用 `sampleLight(lightSample, pdfArea)`。
3. 读取 `coords/normal/emit`，得到 `x/nLight/Le`。
4. 计算 `x-p`、距离平方 `r2`、距离 `r` 和单位方向 `toLight`。
5. 计算两端余弦：

```text
cosSurface = max(0, dot(n, toLight))
cosLight   = max(0, dot(nLight, -toLight))
```

为什么第二项要反向：表面看灯的方向是 `p→x`，灯看表面的方向是 `x→p`。

有效条件：`pdfArea>0`、距离非零、数值有限、两个余弦都为正。
不满足时，本次直接光贡献为零；仍可继续计算间接光，不要因此直接把整个函数返回黑色。

`lightSample.happened` 不会自动变成 true，`lightSample.m/obj` 也不保证有值。
判断采样结果时使用这些接口实际填写的信息，不要按普通求交结果的方式访问它。

### D. 判断“这个采样灯点”是否可见

只取到灯点还不代表能照到当前表面。你要检查从 `p` 到 **采样的那个 `x`**
之间有没有其他几何体。

先处理自相交：

1. 让阴影射线起点沿当前法线向外稍微偏移，得到 `shadowOrigin`。
2. 从 `shadowOrigin` 重新计算指向 `x` 的单位方向和距离 `shadowDistance`。
3. 用这条阴影光线检查遮挡。

偏移量是几何容差，应根据当前场景尺度选择，小到不改变可见几何、大到能避开浮点自相交。
不要依赖方向恰好和法线平行，也不要为了消除黑点不断增大偏移量。

**建议先实现方式一：最近交点是否到达灯点。**

- 对朝 `x` 的阴影射线求最近交点。
- 确认真实命中，并且命中距离与 `shadowDistance` 在合理容差内相同。
- 这样才能认为射线到达了采样位置。

也可以比较命中坐标与 `x` 的距离。由于光线起点有偏移，不能拿“从偏移起点求得的距离”
去和原始 `|x-p|` 做严格相等比较。

常见误判：

- 只判断 `shadowHit.m->hasEmission()`：可能命中另一个灯点或另一个光源。
- 只判断有命中：挡路的盒子也会命中。
- 只比较 `shadowHit.obj` 和整个灯网格的地址：返回的 `obj` 通常是灯内部的三角形指针。
- 使用浮点 `distance == shadowDistance`：很容易出现边界黑条。
- 使用旧 `trace()` 或占位 `intersect()`：本作业主路径应通过 `Scene::intersect()`。

**可选方式二：有限长度遮挡射线。**

把射线终点放在灯点前一个小容差处，设置 `t_max`，该区间内没有命中才表示无遮挡。
这要求包围盒和三角形都严格遵守射线区间；当前三角形已写入区间判断。
选择一种方式写清楚即可，不要同时要求“命中灯”又把灯端点从 `t_max` 区间中排除。

直接光公式仍使用原始 `p/x` 的方向、距离和余弦；偏移后的数据主要用于稳定的可见性测试。

阶段验收：盒子挡住的灯点不产生直接光；无遮挡的可见表面能得到正贡献。

### E. 计算直接光 `L_direct`

只有 C 步数据有效且 D 步可见时，才计算贡献。

使用 `material->eval(travelDir, toLight, n)` 查询 BRDF，记为 `frDirect`。
框架已经返回 `Kd/π`，不要再额外除一次 π。

```text
L_direct = Le × frDirect × cosSurface × cosLight / (r2 × pdfArea)
```

| 因子 | 为什么需要 |
| --- | --- |
| `Le` | 灯自身发出的辐射亮度 |
| `frDirect` | 当前材质把灯光反射到观察方向的能力 |
| `cosSurface` | 灯光照到当前表面时的投影 |
| `cosLight` | 灯面朝向当前表面的程度 |
| `1/r2` | 从灯面面积采样转换到当前点所见方向范围的几何项之一 |
| `1/pdfArea` | 补偿随机选择灯面位置的概率密度 |

`Le` 和 `frDirect` 都是 RGB 向量，框架的向量乘向量表示逐通道相乘，正好用于这里。
不要用 `dotProduct()` 把两个 RGB 向量变成一个数。

注意：这里不应再调用 `material->pdf()` 作为灯面的 PDF。
`sampleLight()` 返回面积密度，材质返回方向密度，它们对应不同的积分测度。

阶段验收：先只返回 `L_direct`。应该能看到灯、被灯直接照亮的表面及遮挡阴影；
没有间接光照到的地方较暗，此时还不能要求完整的墙面颜色传递。

### F. Russian Roulette：决定是否继续间接反弹

使用 `get_random_float()` 与一个统一的存活概率 `P_RR`。

你现在局部写了 `P_RR=0.8`，场景同时已有 `RussianRoulette=0.8`。
建议以场景成员为来源，避免之后修改 `Scene.hpp` 时算法仍使用另一份硬编码数值。

需求：

1. 已经算好的直接光不参与这次随机终止。
2. 以 `P_RR` 的概率进入间接反弹，剩下的概率令 `L_indirect=0`。
3. 终止时仍返回已经得到的 `L_direct`，不是整个函数返回黑色。
4. 存活路径的间接贡献在 G 步除以 `P_RR`。

为什么要补偿：假设只有 80% 的路径继续，则继续的路径需要乘 `1/0.8`，
才能保持期望不被这次随机舍弃压暗。

本作业使用 `0<P_RR<1`；不要把概率随意设为 0 或 1 后仍沿用同一逻辑。
`depth` 用于计数和调试，`maxDepth=1` 字段不会自动终止递归。
若临时加入固定深度上限定位问题，要清楚它会截掉后续能量，不能当作 RR 的等价替代。

### G. 采样间接方向、找下一个表面并递归

这是最值得拆细的一步，按以下顺序实现即可。

**G1：向材质要一个反弹方向。**

调用 `material->sample(travelDir,n)`，得到 `bounceDir`。
当前漫反射实现理论上返回单位方向；创建射线时保持单位方向约定，并确保法线有效。

**G2：查询对应 PDF 和余弦。**

调用 `material->pdf(travelDir,bounceDir,n)` 得到 `pdfDirection`，
计算 `cosBounce=max(0,dot(n,bounceDir))`。

当前是均匀半球采样，所以有效方向的 PDF 为 `1/(2π)`，不是 `cosBounce/π`。
使用接口而不是在这里再硬编码一套密度，便于之后保持材质接口一致。

PDF 无效、非正或余弦不为正时，本次间接贡献为零，保留直接光。
不要为防除零把所有 PDF 无条件替换成 `max(pdf,EPSILON)`；改变密度权重可能引入偏差。

**G3：发射反弹光线，求下一交点 `q`。**

从向外偏移的起点沿 `bounceDir` 创建光线。
使用 `Scene::intersect()` 取得下一交点。

- 未命中：间接贡献为零，因为本场景没有环境照明。
- 命中发光面：按本篇直接/间接分工，间接贡献为零。
- 命中普通非发光面：继续 G4。

**为什么间接撞灯要过滤？** 显式灯面采样已经估计了直接光；若半球采样撞灯时又
无条件把它当递归发光贡献加入，就会再次估计同一类直接光，导致期望偏亮。
“灯不能直接看见”和“间接分支不重复计光”是两件不同的事，B 步与这里要配套。

**G4：递归查询后续贡献。**

将刚才的反弹光线传入 `castRay()`，并使用 `depth+1`，得到 `LiNext`。
注意传入的是反弹光线，不是最初的相机光线，也不是阴影光线。

在这个基础写法里，G3 做一次预检查，递归入口 A 又会求一次相同交点；
这是便于对应作业伪代码的重复计算，不需要一开始就改函数签名优化。
正确性完成后，可考虑用内部辅助函数复用已知交点。

**G5：乘当前表面的反射权重。**

用 `material->eval(travelDir,bounceDir,n)` 查询 `frIndirect`，然后计算：

```text
L_indirect = LiNext × frIndirect × cosBounce / (pdfDirection × P_RR)
```

这里使用的是**当前点 `p` 的材质**，不是下一点 `q` 的材质；
`q` 的反射与发光处理已由递归调用负责。

这条方向积分估计中不要再次乘 `cosLight/r2`；面积光源的几何转换属于 E 步，
这里采样的是反弹方向，公式的测度已经不同。

阶段验收：加入间接光后，原来只靠直接光较暗的区域得到补光，白色表面能出现红绿墙的染色。
单张低 SPP 图会有噪声，不能要求每个像素都比直接光测试图更亮。

### H. 合并返回并覆盖所有控制路径

普通表面的最后一步是返回 `L_direct + L_indirect`。
对照下面的表检查是否有遗漏：

| 场景/分支 | 这次返回什么 |
| --- | --- |
| 当前光线未命中 | 黑色 |
| 当前光线命中灯 | 灯的发光值；与间接分支过滤配套 |
| 直接光样本无效或被遮挡 | `L_direct=0`，仍可计算间接光 |
| RR 没有存活 | 已经算出的直接光 |
| 反弹方向无效、下一跳未命中或撞灯 | 已经算出的直接光 |
| 普通表面且有效递归反弹 | 直接光 + 经过权重补偿的间接光 |

**不要在这个函数里做显示处理。** 不要裁剪到 `[0,1]`，不要 `pow(...,0.6)`，
不要映射到 0～255，也不要除相机的 SPP。高于 1 的线性值可以是合理的发光/亮度值。
这些显示映射和像素平均已经在 `Renderer::Render()` 中处理。

## 4. 可以直接放进编辑器的任务清单

下面只是一组注释，方便你在当前函数里逐块填入自己的实现。

```cpp
// A. 求当前交点；未命中时返回黑色。
// B. 发光面返回发光值；普通表面提取位置、法线、材质。
//    初始化 L_direct、L_indirect。
// C. 采样灯点，取得面积 PDF，计算方向、距离与两个余弦。
// D. 创建避免自相交的阴影光线，验证是否到达采样灯点。
// E. 有效且可见时计算直接光；否则只令直接光为零。
// F. 使用统一的 RR 存活概率决定是否计算间接光。
// G. 存活时：材质采样方向 → PDF/余弦 → 下一交点。
//    仅对非发光命中递归，depth+1，并加入 BRDF/PDF/RR 权重。
// H. 返回两类贡献之和，保证所有分支都有有效返回值。
```

写一块就编译一次。当前只有未命中分支有返回，在填完之前应避免直接进行完整渲染，
否则命中路径可能执行到非 void 函数末尾。阶段性实验可明确让未实现贡献返回零，
并在最终版本中替换为正确计算。

## 5. 每一阶段如何验证

先用小图、低 SPP；最终再恢复满足提交要求的参数。

| 阶段 | 暂时实现到哪 | 重点检查 |
| --- | --- | --- |
| 1 | A+B，普通表面暂时黑色 | 灯是否可见，未命中是否稳定返回 |
| 2 | 加入 C+D+E，暂不做间接光 | 直接照明、遮挡、光源余弦、是否有自相交黑斑 |
| 3 | 加入 F+G | RR 补偿、间接染色、是否递归同一条旧光线 |
| 4 | 完整 H 与数值检查 | 无 NaN/Inf，所有路径有返回，灯没有被重复计入 |
| 5 | 提升 SPP 与分辨率 | 噪声趋势、正式结果与参数记录 |

可以暂时打印少量指定像素/指定射线的数据：

```text
depth、hit.happened、材质是否发光
pdfArea、r2、cosSurface、cosLight、visible
是否通过 RR、pdfDirection、cosBounce
L_direct、L_indirect
```

不要为每一次路径反弹都打印，输出量可能压过渲染计算本身。
固定深度上限、关掉间接项等都只能是标记清楚的阶段实验，最终应恢复完整逻辑。

降低 RR 概率通常让平均路径更短、噪声变化，但足够多样本下不应系统性把结果压暗。
比较两张随机低 SPP 图片时不能要求逐像素相等。
框架当前没有固定随机种子的入口，严谨比较应看多样本统计趋势，而不是一张图的偶然亮暗。

## 6. 故障现象与优先排查项

| 现象 | 优先检查 |
| --- | --- |
| 编译报 `ture` 未声明 | 包围盒成功返回的拼写 |
| 灯是黑的，其他地方有光 | B 步的直接发光返回是否实现 |
| 灯附近或墙面出现黑条 | 阴影起点、端点容差、零厚度包围盒与相切 |
| 普通表面全部是黑的 | 灯面法线的余弦是否用了反方向，PDF 和可见性是否有效 |
| 整体明显偏亮 | 间接撞灯是否重复计入、是否遗漏除 PDF、RGB 是否错误累加 |
| 加 RR 后明显偏暗 | 存活贡献是否除 `P_RR`，失败分支是否误删直接光 |
| 间接光消失 | 是否对非发光命中递归、是否误用了旧 `trace()`、递归方向是否正确 |
| 递归不停止或栈溢出 | RR 概率与比较方向，是否每层重新抽样，起点是否自相交 |
| NaN、白点或异常极亮 | 零距离、无效 PDF、法线/方向归一化、有限值检查 |
| 调高 SPP 仍有系统性亮暗偏差 | 光照公式、重复计光、采样分布与 PDF 是否一致 |

## 7. 框架已有的采样边界，避免误以为全是 castRay 的错

当前 `BVHAccel::Sample()` 仍使用 `sqrt(random)*总面积` 选择累计面积区间，
与其返回的均匀面积 PDF 不一致；默认网格灯也走这条链。
此外，`Scene::sampleLight()` 在多个发光对象下没有将对象选择概率乘入输出 PDF。

这些是框架采样层的已有问题，不是应在 `castRay()` 中另乘一个随意常数来补偿的问题。
先按本篇理解并完成函数结构；做严格收敛/能量比较时，需要同时核对采样器。
详见 [框架函数讲解](Assignment7_框架函数讲解.md) 第 12 节。

## 8. 最终自查清单

- [ ] 当前交点求一次后复用，未命中返回黑色。
- [ ] 访问材质前确认命中有效；命中灯使用材质发光值。
- [ ] 直接光使用灯面的面积 PDF；间接光使用材质的方向 PDF。
- [ ] 两个光源几何余弦的方向正确，`r2` 没有被误写成距离。
- [ ] 可见性针对采样灯点，偏移后的起点、方向和比较距离一致。
- [ ] RR 只终止间接部分，存活贡献除以同一个存活概率。
- [ ] 间接分支仅对普通非发光命中递归，避免重复直接光。
- [ ] 递归使用新的反弹光线和 `depth+1`，反射权重来自当前材质。
- [ ] 没有重复除 π、重复除 SPP 或提前进行显示映射。
- [ ] 所有分支返回明确的 RGB 值，零距离与非正 PDF 不进入除法。
- [ ] 通过阶段验证后，再生成至少 512×512、8 SPP 的正式图并记录耗时。

最合适的起手顺序是：**先让灯可见，再做直接光与阴影，最后加入 RR 和间接反弹。**
